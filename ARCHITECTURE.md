# Claim Autopsy — Architecture & Quality Plan

> AI OpenBuild Hackathon. Submission deadline 2026-12-10. Solo builder.
> This document is the ruler: **direction / standard / acceptance criteria (with program-rejectable counterexamples) / architecture**. No work starts until all four are set. Every decision is checked back against this table, not against intuition.

---

## 0. One-line definition

**Paste an online claim. Claim Autopsy splits it into independently checkable atomic claims, finds supporting and refuting evidence for each, labels what is supported, what is under-evidenced and what cannot be determined — and exposes every step of the reasoning as an inspectable audit trail.** It also runs the other direction: **paste the claim and the document it cites, and every atom is audited against that document** — supported, refuted, or not stated in the source, with the exact sentence and character range. The first mode's protagonist is Evidence + Refusal; the second mode's protagonist is the citation that either holds or does not, and it always returns a finding because the evidence is supplied with the input.

The difference from "yet another AI chatbox": the protagonist is not the Answer but **Evidence + Refusal**. The product turns "does the AI dare to say *I don't know*" from a slogan into a visible, clickable, reproducible interaction.

## 1. Direction

### 1.1 Derived backwards from the scoring rubric

| Criterion | Weight | How this design scores |
|---|---|---|
| AI Integration & Technical Execution | 30% | Pluggable LLM provider, semantic relevance re-ranking **plus semantic recall when rules retrieve nothing**, deterministic offline fallback with explicit `degraded` label, and a measured rule-vs-AI delta on deep paraphrases |
| Originality & Problem Framing | 25% | Framing: "in the age of AI hallucination, how can a normal person tell whether a sentence is trustworthy?" Original move: turning the honesty mechanism (refusal / citation / audit trail) from a defensive document into the product itself |
| Usefulness & User Experience | 25% | No login, 30-second playable, one-click examples, clickable evidence, visible audit trail, fully English |
| Testing & Communication | 20% | Programmable gates, reproducible failure case, credits, limitations, honest disclosure of benchmark class distribution |

Tie-breakers favour AI integration and originality — the two strongest axes here.

### 1.2 Explicitly out of scope

- No general chat, no multi-turn conversation — only `claim → evidence verdict`.
- No personal or private data; the built-in corpus is public, checkable claims with transparent synthetic demos.
- No claim of "fact-checking accuracy" unsupported by real user samples.
- No accounts, no cloud database — stays local, offline-capable, link-and-play.

## 2. Standard — what "quality" means here

| Attribute | Definition | Design decision |
|---|---|---|
| **Q1 Verifiability** | Every verdict traces to a concrete, clickable source | Citation is mandatory; no citation → no verdict |
| **Q2 Honesty / fail-closed** | Insufficient evidence must produce refusal, never fabrication | Three states: `supported` / `refuted` / `undetermined`; below-threshold → refusal with explicit "what is missing" |
| **Q3 Explainability** | The user can see every step that produced the verdict | Structured trace: decompose → retrieve → semantic → adjudicate, expandable in UI |
| **Q4 Playability** | A stranger plays in 30 seconds with zero setup | Single HTML file, one-click examples, offline mode, instant results |
| **Q5 Reproducibility** | Same input → same verdict in offline mode | Deterministic rules, fixed corpus, run tags with real evidence files |
| **Q6 Coverage** | Unseen common claims are not all refused | 112 evidence cards across 41 verified authoritative sources |
| **Q7 Semantic robustness** | Same fact, different wording → same verdict | Synonym normalization + LLM semantic relevance, offline fallback |
| **Q8 Anti-overreach** | An AI suggestion alone cannot create a verdict | Zero legal citation → forced `undetermined`, even if AI says otherwise |
| **Q9 Quantifiability** | Capability metrics are computed live, never pre-filled | Held-out golden set, paraphrase pairs, front/back-end comparison |
| **Q10 Polarity correctness** | Negated and contrary claims inherit the opposite stance, never the original one | Dedicated negation layer + 8 negation cases + gate A16 |
| **Q11 Class balance** | A constant-"refuted" guesser must not look competent | Each verdict class ≥10 in the held-out set; distribution disclosed in SUBMISSION |
| **Q12 Measurable AI contribution** | AI has a job whose removal changes a measured number | Semantic relevance re-ranks retrieved cards **and**, on rule-zero-recall inputs, AI does same-proposition recall from the full corpus so a real verdict can be reached. `tools/measure_ai_lift.py` measures rule-only vs rule+AI on deep paraphrases; without a key it prints `SKIPPED` — never an invented number |
| **Q15 Same-proposition recall** | A true claim phrased with no shared vocabulary still finds its evidence | When lexical retrieval returns zero hits, the LLM may nominate real card_ids that assert the same proposition; **the stance is read from the card, never from the AI**; fabricated claims still refuse |
| **Q13 Full-English delivery** | All judge-facing artefacts are in English | UI, corpus, docs, benchmarks and screenshots in English; no CJK in deliverables |
| **Q14 Doc-code consistency** | Every file referenced in docs exists | Gate A17 checks referenced paths and scans for stray secrets |
| **Q16 Static-page AI visibility** | A judge who only clicks the public link can *see* the AI contribution without a key, an install or an account | The static page carries a side-by-side contrast panel replaying real recorded API calls: offline core refuses, AI-assisted recall reaches a verdict with a real card. Labelled "recorded, not live" — never presented as a live model call |
| **Q17 Coverage transparency** | A refusal explains its own boundary instead of looking like a broken product | Every `undetermined` result shows the nearest covered topics and links into a searchable corpus browser; the copy states that refusal is a corpus-coverage boundary, not a judgement that the claim is false |
| **Q18 Anatomy visibility** | The product named "Autopsy" shows the dissection, not just the badge | The claim → decomposition → polarity → retrieval → citation gate → three-state chain is rendered as visible nodes rather than hidden in a collapsed text block |
| **Q23 Untrusted input** | A pasted claim cannot act as prompt syntax, however it is phrased | Claim text is normalised, size-bounded, delimiter-escaped and line-quoted before it reaches a model; the system prompt names the block as untrusted data; verdicts are unchanged by injected instructions |
| **Q24 Offline claim is testable** | "No network required" must be a measured property, not a sentence in a README | The pipeline runs in a child process with DNS and connection calls disabled; verdicts stay identical and a forced model call fails closed |
| **Q25 Precision over adjacency** | A card about the same topic is not evidence about a different relation or a different part of a compound claim | A causal card cannot decide a prevention claim; a compound "A and B" whose halves conflict is split into two atoms, not averaged into one `supported`; a coordinated object ("cold and flu") stays one atom rather than being truncated to its first noun |
| **Q26 Scope is part of the claim** | A claim's population and subject are part of what it asserts, so evidence has to match them, not merely the topic words | A card about adults may not decide a claim about children, and a card about infants may not decide a claim about everyone, and population labels do not count as topical overlap — they say *who*, not *what* |
| **Q30 An amount is part of the claim** | A card that measured one dose says nothing about another dose, and a card about one relation says nothing about a different relation | 400 mcg folic acid cannot settle 40 mcg or 4000 mcg; "at least 60% alcohol" cannot decide whether 40% works; a poisoning card cannot decide an efficacy claim. Durations are not doses |
| **Q31 A contradiction is labelled** | When one paste asserts two things that cannot both be true, the report must say so rather than presenting the verdicts side by side | Negation asymmetry, opposite predicates and opposite relations over a shared subject are printed as a contradiction with its basis; known synonyms are folded first so "round" and "spherical" are never flagged |
| **Q27 Negation is a property** | Polarity correctness is a law over the corpus, not a handful of hand-picked fixtures | Every affirmative golden claim inverted mechanically must move to the other decided state; every double negation must refuse; a negator that changes nothing must fail the test |
| **Q28 A citation carries a receipt** | "Trust this verdict because a source exists" is not enough; the reader must be able to see what matched | Every citation names the content words that literally occur in both the claim and the card, and the page prints them; a citation with no shared vocabulary is visible as such |
| **Q29 A refusal is diagnosed** | "No evidence found" is a shrug; a refusal should say which card came closest and which guard stopped it | The nearest rejected card is named with a machine-checkable reason code (`different_population`, `different_relation`, `no_shared_topic`, `missing_required_topic`), and the verdict must stay a refusal |

**Priority**: Q2 > Q10 > Q1 > Q3 > Q4 > Q5. Honesty is the soul of this product — and a product about evidence consistency that labels "Earth is not round" as *supported* has no soul at all.

## 3. Acceptance criteria — each with a program-rejectable counterexample

> Every gate is run fresh. Numbers are never copied from a previous run.

| ID | Criterion | Pass condition | Counterexample that must FAIL |
|---|---|---|---|
| A1 | No evidence → refusal | Out-of-corpus claim returns `undetermined` with an explicit "missing" note | Any `supported` / `refuted` on zero evidence |
| A2 | Mandatory citations | Every verdict carries source_id + snippet + resolvable URL | Verdict with empty or malformed citation |
| A3 | Correct decomposition | A 3-assertion input (comma and enumeration-mark variants) splits into ≥3 atoms | Merged atoms, or a non-checkable subjective fragment |
| A4 | Complete audit trail | Each claim has decompose / retrieve / semantic / adjudicate traces | Any missing trace step |
| A5 | 30-second play | `index.html` opens via `file://`, one click produces a full result | Login, key or network required for the main flow |
| A6 | Reproducible failure | At least one example stably returns `undetermined` | Every example returns a verdict |
| A7 | Offline determinism | Two offline runs are field-for-field identical | Any differing verdict |
| A8 | No secrets | No API-key literals in code or evidence | `sk-` followed by real key material |
| A9 | Honest boundary | README / SUBMISSION state "mechanism demo, not authoritative fact-checking" | Claims of "100% accurate" or "validated with real users" |
| A10 | Corpus & source trust | ≥40 cards, ≥8 sources, all URLs in the authority whitelist | Placeholder / non-whitelisted URL |
| A11 | Held-out accuracy | ≥30 cases, accuracy ≥90%, zero-evidence false positives = 0 | Any no-evidence case with a verdict |
| A12 | Paraphrase robustness | ≥8 pairs, consistency ≥85% | ≥2 pairs dropping from verdict to refusal |
| A13 | AI anti-overreach | Mock AI says "supported" with zero legal citations → `undetermined` | Any verdict created by AI suggestion alone |
| A14 | Front/back-end sync | Python and Node verdicts identical on the full golden set | Any single mismatch |
| A15 | Citation relevance | No unrelated source may enter the citation list | "Flu vaccine contains live virus" retrieving the autism card |
| **A16** | **Polarity correctness** | `Earth is not round → refuted`; `Earth is flat → refuted`; `Earth is not flat → supported`; `Flu vaccine will not give you flu → supported`; double negation → `undetermined` | Any wrong verdict on these fixtures |
| **A17** | **Hygiene & doc-code consistency** | No `sk-` literal outside `evidence/history/`; every path referenced in docs exists; no CJK in deliverable files | Any stray secret, dangling path, or CJK in a deliverable |
| **A18** | **AI semantic recall** | On ≥5 deep-paraphrase inputs where rule retrieval = 0 hits, rule+AI reaches the correct verdict with a real card_id; every recalled id exists in the corpus; recalled stance equals the card's own stored stance; a fabricated claim stays `undetermined` | AI inventing a card id, overriding a stored stance, or turning a no-evidence claim into a verdict |
| **A19** | **Recorded-replay integrity** | Every replay case in `data/ai_recall_replay.json` was produced by a real API run (has a `captured_at` and `model` field), its offline verdict is `undetermined`, every cited card_id exists, every citation stance equals the stored card stance, and the offline reject rate / AI success rate match the live `evidence/ai_lift.json` | A hand-written replay case, a fake card id, an AI-authored stance, an offline verdict that is not `undetermined`, or a replay number contradicting the measured benchmark |
| **A20** | **Coverage transparency on the page** | The built `web/index.html` contains a corpus browser wired to all 112 cards, and the front-end kernel attaches a coverage hint to every `undetermined` verdict; no CJK, no key literal | A refusal with no coverage hint, a browser listing fewer than 112 cards, or a static page claiming a live model call |
| **A21** | **Unreadable-input gate** | Non-English, empty or claim-less input returns an explicit `unsupported_input` notice (kind / title / body / action) with zero claims and zero verdicts — in the kernel *and* in the rendered page — while an English control input still decides | A silent `Claims: 0` with no notice, a verdict produced from unreadable text, or a notice that exists only in the kernel and is never rendered |
| **A22** | **Adversarial input discipline** | Three injection payloads (`ignore previous instructions`, a forged `System:` turn, a forged `</claim_text>` block close) leave the verdict of their host claim unchanged and never earn a verdict of their own; the model prompt contains exactly one closing delimiter with the payload escaped and every line quoted; the system prompt names the block as untrusted; a 7700-character paste is refused as `too_long` with a notice instead of being truncated; the quoting check rejects a deliberately unquoted counterexample | Claim text concatenated raw into a prompt, an injected fragment that reaches `supported`/`refuted`, silent truncation of an oversized paste, or a check that cannot fail when the sanitiser is removed |
| **A23** | **Offline isolation** | With `socket.create_connection` and `socket.getaddrinfo` disabled and a dummy key present, three claims produce the same verdicts as in-process analysis, and the forced model call returns an error rather than a result; a tampered verdict list fails the comparison | Any verdict that changes when the network is removed, a model call that succeeds without a network, or a comparison that accepts a mutated result |
| **A24** | **Precision traps** | Seven probes behave as named: a contradictory compound splits into `supported` + `refuted`; a coordinated object keeps its second noun; a prevention claim is not decided by a causation card; adjacent product and adjacent outcome claims refuse; a quantifier overreach never reaches `supported`; the plain control still decides. The same seven are replayed through the real front-end kernel in Node, and a tampered case list is rejected | A single `supported` for "the Earth is round and flat", a dropped "flu" from "cold and flu", a prevention claim refuted by a causation card, a keyword-adjacent citation, or any Python/JS divergence on these probes |
| **A25** | **Population scope** | Eight probes in both kernels: five claims narrowed to children, infants, pregnancy or adults must refuse because every matching card is population-unmarked; three controls whose population matches the card must still decide ("unsafe for pregnant women", "infant's immune system", plus a dose-worded claim that must not be over-refused). A tampered case list is rejected | A pediatric claim decided by an adult card, a "pregnant women" card deciding an MSG claim on coverage alone, or controls collapsing into refusals |
| **A26** | **Negation property** | Every affirmative golden claim is inverted with one mechanical rule (40 claims), must be decided before, and must move to the other decided state after; each claim already carrying a negation is given one more ("It is not true that …") and must refuse (11 claims); an identity negator must fail the same test | A negation that leaves the verdict unchanged, an inversion that lands on `undetermined`, a guessed double negation, or a property test that passes with no transformation at all |
| **A27** | **Citation receipts** | For three probes, every citation must carry at least one content word that literally occurs in the claim text, the rendered page must print "Matched on" for them, and Python and the front-end kernel must produce identical anchor lists; a citation with an empty list must be rejected by the same check | A verdict whose citations share no vocabulary with the claim, an anchor printed but absent from the claim, or UI/kernel divergence in what was matched |
| **A28** | **Refusal diagnosis** | Five probes: four must name their closest card and the guard that stopped it (`E086`/different population, `E009`/different relation, `E072`/different population, `E086`/missing required topic) and stay `undetermined`; one claim with no near card must produce an empty near-miss list rather than an invented one. Python and the front-end must agree card-for-card and reason-for-reason | A verdict leaking out of a guarded case, a near-miss naming the wrong card or the wrong reason, an invented near-miss for an unrelated claim, or kernel/UI divergence |
| **A29** | **Dose and efficacy scope** | Six probes in both kernels: 400 mcg folic acid decides (`supported`); 40 mcg and 4000 mcg refuse with E087 named as the near card on `different_quantity`; 60% alcohol decides; 40% alcohol refuses with E081 named on `different_relation` (a poisoning card cannot decide efficacy); plain hand-washing decides. Python and the page must agree on verdict and full near-miss list | A 40 mcg claim decided by a 400 mcg card, a 4000 mcg claim decided the same way, an efficacy claim decided by a poisoning card, a dose mismatch that is silently ignored, or kernel/UI divergence on the near list |
| **A30** | **Cross-atom consistency** | Five submissions: a round/flat pair, a negated pair and a causes/prevents pair must each be labelled with their basis (`antonym:round/flat`, `negation`, `opposite_relation:cause/prevent`) and keep two separate atoms; a round/spherical synonym pair and two unrelated atoms must stay unlabelled. Python and the page are compared pair for pair | An averaged single verdict for a contradictory paste, a synonym pair flagged as a conflict, an unrelated pair flagged, a conflict that changes a verdict, or kernel/UI divergence |
| **A32** | **Held-out guard benchmark** | 39 probes in `data/guard_set.json` (dose, percent, relation, population, attribute, prohibition, negation, split, separator, relative polarity, strength, subject, outcome class, plus 7 controls) must produce the exact verdict, atom count, cited card and near-miss reason in both kernels. The set must be disjoint from the golden set, and at least 2 controls must still decide | A probe copied from the golden set (no held-out claim), a guard that refuses the controls too ("refuse everything"), a mismatched near-miss reason, or kernel/UI divergence |
| **A33** | **Chain reasoning** | Five submissions: a two-step cause chain with a third atom that denies the derived statement must be flagged; the same pair without the third atom must be derived and labelled; a third atom that agrees must not be flagged; a prevention chain must derive "prevents"; a pair with no shared link must yield no chain. Python and the page are compared case for case | A chain reported without its derivation, an agreeing atom flagged as a conflict, a chain invented from two unrelated sentences, or kernel/UI divergence |
| **A34** | **Snapshot verification** | One snapshot row per card exists (112 today), at least 75 are `verified`, zero are `hash_mismatch`; every verified row carries an excerpt, selector, fetch date and two hashes, and every unresolved row carries a stated reason; each stored paragraph hash is recomputed and must match; three claims must carry their snapshot through the pipeline into the rendered page with identical status, paragraph index and hash prefix; a tampered hash must be rejected | A verdict whose "verified" label was never checked against the paragraph bytes, a citation whose page silently changed, an unresolved card with no reason, a hash mismatch treated as verified, or kernel/UI divergence on the snapshot fields |
| **A31** | **Stance and separator parity** | Four probes in both kernels: "more than 4,000 IU is not recommended" decides with E088 cited and one atom (the separator stays in the number); "alcohol gel prevents the spread of flu" refuses with no citation (an object word does not create a relation match); "10,000 IU is safe" refuses (the card states a different dose and a different predicate); "unsafe for pregnant women" still decides with E009. Verdict, atom list and cited ids must match the page | A dose torn apart at a thousands separator, a prevention claim decided by a causation card through a shared object word, a prohibition scored as a negation, or kernel/UI divergence |
| **A35** | **External regression** | The five external dev slices are recomputed inside the suite from the frozen sample files; each dataset's accuracy and refusal rate must match the published run in `evidence/external_eval_v4.json` within tolerance (0.02 / 0.01); the lowest accuracy-on-decided must stay at 0.5 or above, so decisions cannot silently become guesswork; no external benchmark sentence may appear verbatim in `data/claims.json` or the golden set, so the gap cannot be closed by copying benchmark claims into the corpus | A published external number that no longer recomputes, a kernel that keeps refusing everything (no decisions to score), decisions that fall to a coin flip, or benchmark text smuggled into the corpus or fixtures |

| **A36** | **Endpoint compatibility** | Six predicate endpoints are classified (risk, cure, prevention, transmission, harm, severity) and a shoulder of pairs is declared compatible (risk with prevention, transmission and severity); a susceptibility claim and a cure card must therefore refuse, with `different_outcome` printed, while the plain cure claim is still refuted by the same card; a sentence that only reports that research exists ("several recent studies have looked at …") must be gated as not-a-claim instead of matched to any card; four cases must produce identical verdicts and endpoint near-misses in the Python kernel and in the page | An endpoint mismatch treated as the same proposition, a compatible pair (risk/prevention) split apart, a plain cure claim lost to the new guard, a research-report sentence decided as if it asserted a finding, or kernel/UI divergence |

| **A37** | **Run receipt** | `tools/make_receipt.py` performs the acceptance run itself and writes `evidence/run_receipt.json`; A37 recomputes the receipt's content id, every one of 17 artefact SHA-256s (eight kernel modules including `core/plan.py` and `core/citation.py`, the corpus, golden and guard sets, the citation fixtures, both evidence files, the built page, the front-end kernel, the Node harness), the recorded exit code (0 unless the receipt is the labelled `bootstrap` one), the presence of the audit's own output hash and the recorded interpreter version (a different interpreter is a note, not a violation) | A green tally kept alive after the corpus, the page or the kernel changed, a receipt copied from an older result file instead of a performed run, or a bootstrap receipt presented as a clean run |

| **A38** | **Browser smoke** | `tools/browser_check.py` opens the built `web/index.html` over `file://` in a real browser (Edge, or bundled Chromium), clicks all 10 demo chips, and requires the rendered claim list, the verdict badge class and one citation block per source cited by the page's own engine — 112 corpus items, zero JavaScript `pageerror`, and zero requests to `http://` or `https://`; no browser installed is reported as `skipped_no_browser`, never as green | A page that renders a different verdict than its own engine computed, a dropped or duplicated citation, a demo that throws, a page that needs the network to work, or a "verified" claim about the page that was never clicked |

| **A39** | **Evaluation receipt and one-shot hold-out** | `tools/make_eval_receipt.py` runs the external evaluation and its detail pass itself, then writes `evidence/eval_receipt.json`: two commands with exit codes and output hashes, per-dataset numbers read back from the file the run wrote, and 17 artefact SHA-256s (five sample files, index, both result files, the hold-back result and its ledger, the corpus, six kernel modules). A39 recomputes the receipt id, every hash, zero drift against the live file, and requires the hold-back block to be `opened` exactly once from a frozen file whose hash still matches, with the embedded ledger entry's timestamp and n equal to that run | Numbers quoted without a run behind them, a sample file swapped after scoring, a hold-out silently re-opened, or a receipt that disagrees with the result file it points at |

| **A40** | **Session evidence** | `tools/verify_sessions.py` replays every recorded input through the current engine and compares atom boundaries, verdicts and cited source ids; sessions from an older kernel are labelled `historical:kernel_changed` rather than passed as current; a `customer` or `external-reviewer` session must carry a reviewer block (`outcome` in used / discarded / re_prompted / no_opinion, a non-empty note, `would_pay` in no / unsure / yes), and a self session must not | A transcript that cannot be replayed, a stale record described as today's behaviour, an external session with no statement of what the person did with the output, or the builder's own guess standing in for a customer's opinion |

| **A41** | **Error review** | Every wrong dev decision on the current run must have exactly one entry in `data/error_review.json`; the entry set must equal the wrong set in both directions; each entry is pinned to that run's gold, prediction and cited cards, carries one of three categories, and a `contradictory_benchmark_label` claim must match a group in `evidence/label_conflicts.json` with the exact label counts and row count it asserts; the sample half of the census is recomputed live inside the gate | An error that is quietly tolerated after the number changes, a review entry that outlives the error it describes, a "the label is wrong" claim with no counted group behind it, or counts that only exist because someone typed them |

| **A42** | **Batch and refusal plan** | Twelve texts are run through the page and the Python kernel and compared on verdict, `scope` and `plan` field by field; a refusal must carry a plan and a decided claim must not; a 12-row batch must match the single-claim path row by row with its counts summing to the row count; the 50-row ceiling is exercised with 51 inputs (`n=50, dropped=1`); the rendered table must have one header plus one row per claim with the summary line; and a batch with one row deleted must be rejected | A batch that is adjudicated by a second code path, a refusal that stops at `undetermined` with no next step, a plan that feeds the verdict, a limit that is documented but not enforced, or a page table that disagrees with the kernel |

| **A43** | **API contract** | `serve.py` is started as a real process on an ephemeral port with `LLM_API_KEY` removed from the environment; `/api/health` must report the gate tally and the endpoint list, `/api/status` must declare the offline core, `/api/analyze`, `/api/batch` and `/api/citation` must match the in-process kernel on verdicts, citations, scope, plan and findings, a newline batch must split into lines, empty text must be `400`, an empty citation source must be `400`, the 60-request window must return `429`, and a doctored response must be caught | An endpoint that exists only in the README, a service that silently needs a key, a batch endpoint that bypasses the guards, an unbounded request loop, or a "we have an API" claim no process ever exercised |
| **A44** | **Citation audit** | 12 fixtures in `data/citation_cases.json` are run through the Python kernel, the page's own kernel and `/api/citation`; every fixture's atom list and finding list must match, every atom must receive exactly one of `supported` / `refuted` / `not_in_source`, the three counts must sum to the atom count, the source SHA-256 must be stable across two runs, an empty source must be rejected, and a tampered finding must fail the comparison | A mode that silently reports nothing on some inputs, a "not stated" that is actually a crash or an empty answer, a page and kernel that disagree, or a coverage claim that is a sentence in a README rather than a counted property |

**Overall failure condition**: A1 / A2 / A8 / A16 / A17 / A18 / A19 / A20 failing means the work is not submittable.

## 4. Architecture

### 4.1 Layers and data flow

```
L4  EXPERIENCE   web/index.html — single-page workbench (the primary judge-facing artefact)
    input · list mode (one claim per line) · result · AI contrast panel · anatomy chain
    coverage hint + refusal plan · corpus browser · verdict badges · evidence cards
    audit trail · one-click examples
                    │  fetch /api/analyze, /api/batch  OR  local JS engine (offline)
L3  ORCHESTRATION core/pipeline.py (analyze + analyze_many) · core/plan.py (scope, refusal plan) · core/citation.py (claim vs supplied source)
    decompose → negation → retrieve → recall → semantic → adjudicate → assemble  (+ full trace)
        │                │              │              │
L2  LOGIC        decompose.py   negation.py   evidence.py   semantic.py   recall.py    adjudicate.py
                 (rules/LLM)   (polarity)    (BM25+anchor) (LLM scoring) (AI recall)  (three-state+gate)
        │
L1  AI / DATA    core/llm.py (pluggable provider) · core/recall.py (same-proposition recall)
                 data/claims.json (112 cards / 41 sources) · data/paraphrase_deep.json
                 data/ai_recall_replay.json (14 real recorded dual-path runs → L4 contrast panel)
                 fail-closed: LLM unavailable ⇒ explicitly labelled `degraded`
```

**Important path correction (v4)**: retrieval lives in `core/evidence.py` and the acceptance runner is `core/audit.py`. Earlier versions of this document pointed at core/retrieve.py and tests/acceptance.py, neither of which exists; those references were removed in v4. Gate A17 checks that every backticked path in the docs exists.

### 4.2 Technology

- Python 3.13 standard library only for the offline engine; zero third-party dependencies.
- LLM layer: OpenAI-compatible HTTP via `urllib`; credential read only from `LLM_API_KEY`.
- Retrieval: BM25-lite with IDF-weighted anchor coverage; English word-level tokenization and a synonym-normalisation table.
- Frontend: vanilla HTML/CSS/JS, zero CDN, `file://` openable. The committed HTML is a build artefact of `tools/build_frontend.py`; there is no runtime build step.
- Local API: `http.server` standard library. A static host cannot hold a credential, so the AI contrast panel ships recorded real API runs via `tools/export_ai_replay.py` and is labelled "recorded, not live".

### 4.3 Where quality gates live

- `core/negation.py` + `core/adjudicate.py`: polarity handling (Q10, A16)
- `core/evidence.py`: citation validation and anchor gating (Q1, Q7, A2, A15)
- `core/semantic.py`: LLM relevance as a ranked signal, never a verdict (Q12)
- `core/recall.py`: AI same-proposition recall on rule-zero-recall; stance always read from the stored card (Q15, A18)
- `core/pipeline.py`: structured trace for every step (Q3), and attaches a paragraph snapshot to every citation
- `core/snapshots.py`: loads archived paragraphs + per-card resolution + manual review, recomputes SHA-256 on load, and classifies `verified` / `unresolved` / `page_changed` / `source_changed` / `hash_mismatch` (A34)
- `core/prompt.py`: normalisation, size bound and data-quoting for claim text before any model call (Q23, A22)
- `core/plan.py`: describes what a refusal is missing — whether the claim sits inside the corpus's subject map, the nearest sources as labelled background, and three searches that would settle it (A42)

## 6. Honesty boundaries (shipped in README and SUBMISSION)

- This is a **product demo of evidence consistency and refusal**, not an authoritative fact-checker. The corpus is public common claims plus clearly labelled synthetic demos.
- A verdict means "consistency **given this corpus**", not "truth". `undetermined` means insufficient evidence, not "false".
- When an LLM key is present, semantic relevance is used; without one the engine degrades to deterministic mode and the UI says so explicitly.
- AI OpenBuild's existing CDC-vaccine/autism source discrepancy is presented as a real difference in wording between two pages from the same institution. The tool displays both sides and takes **no position** on the topic.

---

## 7. Benchmark class distribution — disclosed, not hidden

The held-out set is constructed to cover mechanisms, not sampled at random. Its class mix is deliberately skewed toward `refuted` because the common misinformation patterns in the corpus are refutations. This is disclosed in SUBMISSION rather than presented as a balanced real-world accuracy figure. A constant-"refuted" baseline is reported alongside the model score so the number cannot be misread.
